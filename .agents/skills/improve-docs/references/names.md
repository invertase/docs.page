# Names, files, and trademarks

## Product and feature names

Match official capitalization. Features are usually lowercase unless the owner capitalizes them. Don't abbreviate a trademarked name after first mention unless the UI does. Don't use a product name as a verb. Don't put *the* before a product name unless it modifies another noun (*the Transcoder API* is OK).

## Example domains and people

Never use real PII. Domains: `example.com`, `example.org`, `example.net`. Email: `dana@example.com`. Given names from a diverse set (Alex, Amal, Dana, Hao, Kai, Sasha, …). Placeholders like `EMAIL_ADDRESS` are fine.

## Filenames

Lowercase, hyphens between words (`query-data.mdx`), ASCII. Match an existing directory's convention if it already uses underscores. In prose: code font plus the word *file* (`the `docs.json` file`).

On a docs.page site, the path under `docs/` (no extension) is the URL.

## Trademarks

Use a mark only as a modifier of a noun, never as a verb, plural, or possessive. Follow the owner's guidelines. Don't copy logos.
