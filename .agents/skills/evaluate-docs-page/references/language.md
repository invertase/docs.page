# Language and grammar

Person and voice: [person-and-voice.md](person-and-voice.md). Conditions first: [sentence-structure.md](sentence-structure.md).

## Abbreviations

Spell out on first mention, abbreviation in parentheses, then abbreviation alone. Skip the expansion if it doesn't help (*PDF*). Don't abbreviate off-topic terms. *App* and *sync* are short words, not abbreviations.

## Anthropomorphism

Don't give software human senses (*the PC sees*, *the object tells*). Say what it does (*detects*, *specifies*). A CLI or wizard *prompting* for input is not anthropomorphism — don't flag *asks* / *prompts you*.

## Articles

Keep *a*, *an*, and *the*, including in frontmatter `title` and `##` headings (*Create a VM*, not *Create VM*).

## Capitalization

Don't capitalize to invent importance. Don't rely on *Pod* vs *pod* to carry meaning. No all-caps or camel case in prose except official names and code. Sentence case in headings, lists, tables, captions. After a colon, lowercase unless a proper noun, heading, or quotation.

## Contractions

Use common two-word contractions (*don't*, *you're*). Negation contractions are easier to scan than *not*. Don't invent contractions or use three-word ones (*mightn't've*).

## Pluralization and possessives

Don't pluralize or possess a code token or trademark. Add a noun (*the `settings.h` file*, *Chromebook computers*). Don't use *'s* for plurals.

## Prepositions

Ending a sentence with a preposition is fine if it reads more clearly. Don't add extra ones.

## Present tense

Describe general behavior in present tense (*The server sends an acknowledgment*), not *will send*. *Will* is OK for a later result of this procedure, not for unreleased product behavior. Avoid hypothetical *would*.

## Pronouns

Clear antecedent. Follow *this*/*these* with a noun. Use singular *they*. Don't use *he/she*. Keep optional *that*/*which* when dropping them is ambiguous. *Which* (nonrestrictive) takes a comma; *that* (restrictive) does not.

## Verbs on reference pages

Field and method blurbs (including `<Property>` descriptions) use third person (*Creates a task*), not an imperative (*Create a task*). How-to pages stay imperative.
