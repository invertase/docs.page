# Punctuation

## Colons

Text before a colon that introduces a list must be a complete sentence. After a colon, lowercase unless an exception in [language.md](language.md). Prefer a colon over a dash to introduce a definition list.

## Commas

Serial (Oxford) comma. Comma after an introductory phrase. Comma before *and*/*but* when joining two independent clauses (skip if both are very short). Don't comma-splice a dependent clause. Comma before nonrestrictive *which*. Period or semicolon before *however*/*therefore*, comma after.

## Dashes

Em dash for a break in thought; don't overuse. Don't use a dash where a colon belongs in a description list. Don't use `--` as a fake em dash in prose (OK in flags).

## Ellipses

Don't use `...` to trail off in prose. In fences, omit lines with a comment in that language, not a prose ellipsis. Every fence has a copy button, so keep omitted samples clearly incomplete in the surrounding sentence.

## Hyphens

Hyphenate compound modifiers before a noun when needed for clarity. Don't hyphenate *-ly* adverbs. Be consistent on a given term; prefer the form in [word-list.md](word-list.md) when listed.

## Parentheses

Don't hide required information in parentheses. If the parenthetical is a full sentence, put the period inside.

## Periods

No period on headings. Don't leave a period ambiguous after a URL — prefer a descriptive link, or put the URL on its own line. American style: period inside quotation marks unless the quotes wrap a literal token.

## Quotation marks

American double quotes for quotations. Don't use quotes for new terms (use italics) or for UI (use **bold**) or code (use code font).

## Semicolons

Join two closely related independent clauses, or a conjunctive adverb. If a comma would do, prefer the comma or a split sentence.

## Slashes

Avoid *and/or* and *he/she*. Don't use a slash as a casual *or* in prose. OK in paths, URLs, and `application/json`.
